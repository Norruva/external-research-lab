## Own-data training: a new working capability

[Download the new EIDOS application](../eidos-owned-training-application-v1.tar.gz) · [Run instructions](../releases/owned-training-v1/README.md) · [Training data format and limits](../releases/owned-training-v1/TRAINING.md).

The original `eidos.train_support` CLI builds a NEW support-memory registry using only Python's standard library. Provide UTF-8 JSONL rows with id,text,label, exactly20 distinct supports per class and2–256classes, plus a provenance declaration with source,license,citation,rights_basis. Input/provenance/model hashes are recorded; declarations are caller-supplied, not independently verified rights. There is no network resolver, pretrained model, package installation or hosted inference. The command never activates a registry or changes an existing configuration.

The support-only transform uses up to10,000 Unicode word/bigram/character3/4/5 TFIDF features, log1p counts and L2 normalization. Top-five cosine support aggregation is the existing fixed memory method. It is not promoted over the linear classifier: that memory recipe lost to the linear control in the earlier151-choice study. Adding training capability does not imply an accuracy improvement, arbitrary semantic recognition or new-language support.

Bounds:2MiB input,200,000 aggregate text characters,12,000 per utterance,100,000 observed terms and500,000 stored nonzeros. Strict fields, duplicate-key/ID/normalized-word-sequence rejection, exact balanced quotas, finite Unicode, nonempty word sequences and safe bounded regular-file reads are enforced. Output must be a NEW directory under an existing nonsymlink parent. It is private0700 with four0400 model/registry/receipt files, no timestamps/source paths and no automatic activation. Filesystem failure can leave an incomplete new directory; existing caller files are never cleaned up or overwritten. Vocabulary/vectors can reveal source information; no privacy guarantee or hostile same-UID filesystem assurance is claimed.
