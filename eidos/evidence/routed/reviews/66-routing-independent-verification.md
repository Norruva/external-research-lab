# Independent verification plan for a separately versioned routing candidate

Source-only review of the original contextual v3.1 implementation and tests at public commit `db067f0e3d14fd1b315d44e524fca562e697866f`. No model, fit, prediction, study score, package installation, network, vendor service or existing credential was accessed or executed for this review. Existing experiments remain consumed and unchanged. This document proposes authored implementation tests, not a new quality result.

## Existing independent checks and their limits

`tests/test_decision_contextual.py` independently tokenizes/segments raw wire text, reconstructs the declared flat parameter layout without model offsets, evaluates scalar equations without calling encode/forward/private helpers/tape, and compares every parameter derivative with central differences on a tiny D=2/H=2 fixture. Its current absolute gradient tolerance is 3e-7 with epsilon 1e-5. An independent nonrecursive control confirms that repeated static reads differ from recursive pointer updates for one witness. The unknown equal-count candidate test hand-sets one key-position/readout path and checks exact expected softmax masses and correct relative logits.

These are useful. Most other binding/order/unknown-name tests assert that SOME logit changes for fixed parameters, however; this does not show that the question chooses the intended direction/depth or that either answer is correct. Finite-difference agreement by itself can also pass when new routing blocks are dead, symmetric or saturated and both numerical and analytical derivatives are zero. New tests should therefore cover both exact mathematics and separate nondegenerate information-path witnesses.

## Source-proven unknown-instruction collision

Consider identical context and offered options, and these two shifted generator questions for the same subject:

- `From {subject}, move onward once and return the shade.`
- `From {subject}, move onward twice and return the shade.`

If `once` and `twice` are both absent from the learned vocabulary and from context/options, v3.1 produces identical outputs for EVERY parameter setting in exact arithmetic. The prompts have identical token count/order except for one UNK word vector. Their contextual states and pooled question vector are identical. The initial spelling focus includes question words only when they also occur in context, so that focus is unchanged. No candidate membership, fact, read query, pointer value or head feature can observe the replaced spelling. Both copied tokens remain irrelevant to context identity matching. Changing directed traversal depth can change the correct answer even though this model cannot distinguish the questions.

This is a conditional representation proof, not a new evaluation or claim that every shifted question collides. The public generator's literal training templates do not teach these two words. More conditional routing over the SAME collapsed question vector cannot repair this case. A new architecture needs distinguishable instruction features and appropriate original semantic supervision; preserving byte/spelling identity alone does not reveal an unseen word's meaning. Do not encode a privileged `once`/`twice` lookup in inference merely to pass this fixture.

## Independent scalar oracle for the next architecture

Freeze a new architecture/model identifier, flat parameter contract and equations before a scientific fit. Reconstruct parameter offsets from the written shapes, not runtime attributes. Parse raw wire text independently. In the scalar reference, explicitly compute each hop's question/state-conditioned key attention, value attention, fact attention, spelling distribution, state update, any relation/direction mixture, any read-depth/halting mixture, and full-set candidate softmax. Do not reuse new encode/routing/private math helpers or the new autodiff tape.

For example, with copied spelling distribution `mu[h+1,t] = sum_s A[h,s] sum_j beta[h,s,j] I(token[s,j]=t)`, the reference must propagate EVERY key/value/fact-attention dependence through subsequent hops. Treating `mu` or the query state as detached constants in backward can still match a one-hop test and fail multi-hop learning.

If a depth mixture is `rho = softmax(a(q))`, and a candidate feature is `c = sum_h rho[h] c[h]`, the local identity is `dc/da[k] = rho[k] (c[k]-c)`. Include a direct test with distinct `c[h]`, and a separate equal-read control where the derivative correctly vanishes. Relation mixtures have the analogous identity. Shared blocks accumulate derivative contributions from every offered candidate and every read; they must not be overwritten per branch.

## All-coordinate derivative strategy

Use at least two tiny, fully authored numerical fixtures with D=2 and the smallest supported head, three nonidentical facts, two/three differently described options, a nonzero but mixed question/context identity intersection, and unequal copied masses across hops. A second fixture should contain zero initial intersection, repeated context tokens and repeated candidate words to exercise count/set distinctions. Include both output targets across the fixtures. Keep vocabulary small and exercise every vocabulary row rather than declaring success over unused embedding parameters.

Use modest deterministic hand-assigned or seeded parameter values for the numerical fixture so conditional gates are neither exactly symmetric nor saturated; initialization's strong match/boundary biases alone should not define this fixture. Compare loss/logits to the independent scalar reference first. For EVERY coordinate use central differences, initially epsilon 1e-5, scaled as `epsilon * max(1, abs(parameter))`, and a declared absolute-plus-relative tolerance. If stability is in doubt, cross-check 5e-6 and 2e-5 before weakening any tolerance. Restore the parameter in `finally` and verify that the whole parameter vector remains unchanged by gradient computation.

Report/assert finite derivatives and a nonzero aggregate derivative norm in each new query-key, query-value, direction, state-update and depth-control block for at least one deliberately nondegenerate fixture. Do not require every coordinate to be nonzero: legitimate unused rows and algebraic softmax gauges can have zero derivatives. Specify these exceptions. A broad tolerance or dead-block fixture must not become a substitute for chain-rule verification. Resource/tape refusal tests should execute before partial result publication.

## Required independent capacity witnesses

1. **Question alone selects direction.** Hold one short two-token context and two candidate descriptions fixed, with both candidate spellings OOV. Use two known, differently encoded question markers. Set parameters to a declared query-conditioned key/value-position bilinear that reverses the preference for the two token positions. An independently computed sigmoid/softmax must predict reversed correct relative logits. Initial context focus can be zero and the sole fact attention is one, isolating question-to-key/value control from unrelated matching/head effects. This proves an available path, not learned meaning.
2. **Question alone selects read depth.** Use a hand-authored directed chain with newline-separated two-token facts, OOV entity names, fixed context and candidate set. Two known question markers choose the first versus second copied answer. Hand-set key-first/value-last routing, independently compute the recursive transition masses, then let the declared depth mixture choose the requested read. Confirm a static-focus or fixed-depth control cannot satisfy both answers under the same construction. Keep this capacity witness separate from nonsaturated gradient fixtures.
3. **Unknown instruction identity survives, if the new architecture claims it.** Replace one OOV instruction marker with a different same-length/anagram marker, with neither present in context/options, while holding everything else fixed. Demonstrate a fixed-parameter distinction through the claimed byte/character channel. No correct semantics can be required for arbitrary unseen markers without supervision. If no such channel exists, retain explicit refusal/limitation rather than claim unknown-word generalization.
4. **Question order survives, if claimed.** Construct a same-multiset order swap in the question that asks for different noncommuting relation composition. A fixed-parameter witness should distinguish it without changing context/options. Do not claim three reads inherently preserve operation order if the question encoder still pools it away.
5. **Entity renaming equivariance.** Bijectively rename ONLY entity tokens that are all OOV in the fixed model, consistently across context/prompt/candidate descriptions, preserving tokenization and facts. Probabilities should correspond exactly or within a tight floating tolerance, because pointer identity changes consistently while UNK vectors do not. Test repeated-name/anagram names and a rename that would accidentally merge two identities, which must not be treated as an invariance. Known-vocabulary replacements need not be invariant.
6. **Candidate/transport invariances.** Opaque option IDs, request IDs, reordered options and SCORE anchor metadata must not supply routing semantics. Check corresponding logits/probabilities, not only the top answer. Duplicate candidate descriptions have identical logits. If each candidate logit is computed independently of other offered candidates, adding a distractor preserves old pairwise log-odds and renormalizes the complete distribution; this is a mathematical property, not proof the distractor is semantically irrelevant.
7. **Fact order and normalization.** Reorder complete facts while preserving their internal token order; if no global fact-position feature is declared, corresponding results should agree up to summation rounding. Unicode NFKC/case normalization must remain consistent. Unknown-name equality is based on normalized spelling, not anagram or shared embedding equality.
8. **Neutral-prefix/field-order stresses are learned-behavior checks.** The local encoder is not designed to be exactly invariant to inserting a neutral prefix or reordering a fact's fields. Do not assert exact invariance for arbitrary parameters. Use explicitly supervised training-only contrast sets, keep these controls out of the later quality cohort, and disclose their role as adaptive diagnostics.

## Shortcut and interpretation controls

A softmax can sharpen an irrelevant candidate-frequency signal without learning a relation. Test same context/options with opposite gold induced only by the question, and pair groups whose answers change while word counts stay fixed. Match the candidate descriptions/ordering across each question contrast. Cross-entropy improvement, answer sensitivity and correct normalization are not a substitute for both variants being correct. A model can route its key/value attentions identically at all hops yet fit a short task through direct candidate features; deliberately disable the proposed new query/depth path in a hand-set witness and show the predicted distinction disappears.

A direction/depth gate can collapse to one branch, especially with symmetric initialization. Avoid initialization where all mixture outputs are equal and gate gradients are zero. Do not “fix” collapse by selecting a checkpoint on exposed held-out accuracy. Inspect training-only gate gradients/contrasts under a new declared scope, then freeze the complete recipe and a separate exposure-disjoint quality challenge. Persist any failed attempt. Authored mechanism tests and static proofs cannot establish 95% natural-language accuracy, LAYA/JEV superiority, calibration, or production readiness.
