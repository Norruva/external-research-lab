## Role and metadata separation

`run_routed_candidate_v2.py:56` constructs mounts by role. Generation receives the hash-only exposure input. Resource probe/preflight/train receive only `training.jsonl` and provenance; revised preflight additionally receives the numerical probe receipt. Prediction receives the fitted artifact and `requests.jsonl`; score receives gold and complete predictions without weights/training. There is no prior ledger, label sidecar, old artifact, hosted service, original workspace or credential/configuration mount in prediction. The shared control source contains generic paths/branch code, not actual gold answers. Source modules include the finite generator/oracle definitions as code, but the inference wrapper invokes the routed network, not the oracle; raw world/task ledgers are not available to it.

Prepared source, control, runner, protocol and exposure hashes are checked before a revised study stage (`run_routed_candidate_v2.py:48`). Staged files and role inputs are pinned, readonly in the inner namespace, with a cleared environment, loopback-only network namespace, refused route probe, per-process CPU/address-space limits and outer timeout. Stage directories refuse overwrite, and the revised preflight has a separately named v2 directory. These controls preserve initial generation/preflight receipts rather than pretending they ran with revised source. They are per-process plus parent watchdogs, not an aggregate cgroup guarantee.

`routed_candidate_control_v2.py:66` puts role/family/pair/contrast metadata into gold only. The inference request contains context, prompt, options, kind and administrative ID. The routed encoder consumes context/prompt/description text (`decision_routed.py:367`) and preserves option IDs only for output alignment/validation; it does not encode request IDs or source groups as semantics. Thus the role-bearing request-ID prefix is not a discovered target leakage path in the model.

## Pairing and contrast scoring

Generator pairing keys include source group, style and task index (`routed_curriculum.py:244`). Each key has exactly two counterfactual variants, even though training exposes two renderings. The scorer groups by role, source group, paired key and kind, asserts every group has two members, and compares semantic descriptions rather than opaque IDs (`routed_candidate_control_v2.py:156`). This correctly avoids mixing renderings or comparing label IDs whose spellings differ across requests.

Seven hue queries share byte-identical context and literal options per world/variant/style. Their subject is fixed, while depth, incoming/outgoing direction and points/cites relation select different answers. Options are created once outside the task loop, with seeds independent of a task's target (`routed_curriculum.py:229`). All five hues rotate nontrivially between variants; the inverse-binding question retains its base hue, so its correct entity also changes. The model does not receive these task annotations.

Contrast IDs separate the seven-question hue set from the one-row inverse-binding set. Scoring includes only non-singleton groups in `contrast_sets` and `all_correct`, so the inverse singleton cannot inflate the question-control success count (`routed_candidate_control_v2.py:183`). A complete seven-question correct set is strong evidence of correct decisions on that authored context. However, `top_answer_varies_when_gold_varies` means **any** predicted-answer variation across seven questions; it does not isolate correct depth, direction or relation control and must not be described as doing so. Dedicated depth/direction/relation IDs exist in the private sidecar but are not separate metrics in this frozen scorer. That is a scope limit, not an arithmetic bug in the metric it actually names.

Option IDs/order are rerandomized between counterfactual variants. Therefore top-answer-change counts alone are not a pure intervention isolating hue binding: in exact probability ties, the scorer's sorted-ID tie rule can produce different semantic top choices. This does not affect the frozen same-context/same-options question contrast or imply leakage into neural probabilities. Disclose both-correct and accuracy, and avoid presenting answer-change counts alone as a causal reasoning demonstration.

The scorer checks one-to-one request identity, offered-option identity, kind, finite bounded probabilities summing to one, review-only output and absent calibrated confidence. Role/family accuracy, NLL, multiclass Brier and analytic uniform expected accuracy are aggregated from one prediction file. It computes the predeclared gate independently for all four held-out roles (`routed_candidate_control_v2.py:186`), requiring each accuracy>=.95. With32 rows this means at least31/32 per slice. No bootstrap/IID interval or deployment decision is manufactured.

## Structural exposure exclusion

`routed_curriculum.py:204` computes both full two-relation structure hashes and old-compatible points/hue projection hashes for BOTH hue-rotation variants. Selection rejects supplied old hashes and earlier accepted structures of the same representation; full-world hashes and source-group identity are also kept distinct. The old-compatible projection uses name-sorted nodes and `(hue, points-successor-index)` tuples, matching the prior one-relation schema. Generation uses a fixed seed and resampling criteria based on hashes, not model outputs, losses or targets. The exclusion file lists only old hashes and ledger digests; no old text/labels are passed to this generation.

The generate control additionally asserts prior projected-hash disjointness, exact expected role counts128/32/32/32/32 and group counts4/2/2/2/2 (`routed_candidate_control_v2.py:54`). It then separates requests from labels. Source-level filtering also checks the new full hash; the extra control assertion checks only the old projection, which is adequate as a redundant assertion rather than the sole enforcement.

This is exact ordered structure exclusion, not graph-isomorphism independence. All worlds are two five-cycles on five nodes with a small shared hue vocabulary; many abstract mechanisms are deliberately reused. Cites-only projections are not separately excluded against the old points corpus; the declared protocol specifically excludes the original points projection, and no stronger all-relation semantic-independence claim is justified. Query subjects and finite answer/rank frequencies can remain imbalanced. The generator reports shortcut inventories but does not prove full balance.

## Composition and probability interpretation

Training explicitly renders two styles and covers all known-name lexemes using its first two groups. It accumulates training context/question lexemes and rejects a held-out nonentity lexeme absent from that training exposure (`routed_curriculum.py:249`, `:278`). New-composition/joint use a third arrangement of familiar operator words; novel_entities/joint separately change entity spellings. The model has no right to treat character buckets as grounding an unknown operator's meaning. Protocol67 explicitly states that this evaluation target differs from the prior unknown-wording challenge. A higher new score would not be a controlled apples-to-apples gain over v3.1; both architecture and supervision/evaluation target changed.

The resource probe computes one arbitrary-target training gradient, does no optimizer step and discards objective/gradient values. This is a resource/finiteness probe, not a semantic quality estimate. Preflight uses two-times observed gradient time plus setup and fixed reserve thresholds, as frozen in protocol68. This is a heuristic conservative estimate, not a bound on all fitted parameter states or objectives; the actual hard CPU/wall/tape/memory guards remain necessary. A resource-only revision before any scientific fitting/quality is distinguishable from selecting a recipe on held-out scores, provided the preserved receipts confirm the stated chronology.

Even all four synthetic gates passing would support only this tiny authored finite mechanism exercise: two paired groups per held-out slice and dependent questions/variants. It would establish neither general95% natural-language performance, calibrated confidence, production readiness nor superiority over LAYA/JEV. Those restrictions are present in protocols67/68 and the score metadata. No vendor services or fresh reference execution are part of this run.
